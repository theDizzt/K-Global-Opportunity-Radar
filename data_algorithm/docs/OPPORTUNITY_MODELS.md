# 협력 기회 다중 모델 v1

## 왜 하나의 종합점수를 바로 만들지 않는가

현재 데이터가 답할 수 있는 질문은 서로 다르다.

- 과거 한국 사업이 이어질 가능성은 어느 정도인가?
- 한국 ODA가 이미 많이 투입된 분야인가?
- 사업 수행 경험과 기관 기반이 존재하는가?
- 외교·정책 문서에서 구체적인 협력 근거가 관찰되는가?
- 해당 분야의 개발 결과에 실제 격차가 존재하는가?

이 질문을 근거 수준이 다른 상태에서 하나의 가중합으로 합치면, 데이터가 없는
항목이 0점으로 오인되고 설명하기 어려운 순위가 만들어진다. 따라서 v1은 각
모델을 별도로 계산하고 다음 상태를 함께 저장한다.

| 근거 상태 | 의미 |
|---|---|
| `validated_predictive` | 시간 순서에 따른 외부 구간 검증을 통과한 예측모형 |
| `descriptive_only` | 관측 자료의 상대적 위치를 나타내는 기술통계 |
| `rule_based_evidence` | 사전 정의한 정책 근거 규칙의 계산 결과 |
| `insufficient_data` | 0점이 아니라 판단에 필요한 자료가 없음 |
| `not_validated` | 예측모형 자체가 아직 검증되지 않음 |

기존 `score_snapshot`은 유지한다. 새 결과는
`opportunity_model_score`, `opportunity_candidate_profile`에 병행 저장하므로
기존 백엔드 계약을 깨지 않는다.

## 모델 1. 협력 연속성

질문은 “이 국가·분야에서 향후 2년 안에 새로운 한국 ODA 사업이 시작될
가능성이 높은가?”이다.

현재 채택된 모형은 L2 정규화 로지스틱 회귀다.

```text
logit(p) =
  0.471
  + 2.047 × z(log(1 + 최근 3년 사업 수))
  - 0.193 × z(마지막 사업 이후 경과연수)
  + 0.009 × z(데이터 충족률)
```

2019~2020년을 학습하고 2021~2022년을 미래 검증 구간으로 사용했을 때
구조모형 Brier score는 0.1341, Average Precision은 0.9095였다. 외교 문서
신호를 추가해도 성능이 안정적으로 개선되지 않아 현재는 외교 변수를 예측확률에
사용하지 않는다.

이 점수는 **협력의 반복 가능성**이지 개발 수요나 신규 시장성을 뜻하지 않는다.

## 모델 2. 한국 측 공급 강도

최근 관측 가능한 3년 동안 한국이 해당 국가·분야에 투입한 사업 수와 약정액을
137개 수원국·8개 분야 분포에서 비교한다.

```text
공급강도 =
  0.60 × 사업 수 경험백분위
  + 0.40 × 약정액 경험백분위
```

약정액이 하나도 관측되지 않으면 사업 수 백분위만 사용하고 데이터 충족률을
0.6으로 낮춘다. 0건은 0점으로 고정해, 0이 많은 분포에서 중간순위가 부여되는
문제를 막는다.

이 모델은 **한국 ODA 공급 강도**만 나타낸다. 다른 공여국의 사업을 포함하지
않았으므로 `포화도`, `경쟁강도`, `미개척 시장`이라고 해석하면 안 된다. 향후
OECD CRS 전체 공여국 자료가 들어오면 전체 공급과 한국 점유를 분리해야 한다.

## 모델 3. 전체 공여국 포화도와 한국 점유율

OECD CRS 2019~2024 전체 공여국 파일을 스트리밍으로 읽어
`연도 × 공여국 × 수원국 × 분야` 단위로 집계한다. 원문 2,151,752행 가운데
국가와 현재 8개 분야로 해석 가능한 1,335,299행이 119,246개 집계로 저장됐다.
지역·전세계 합계와 현재 서비스 범위 밖 목적코드는 제외했다.

최근 3년의 양수 집행액을 기본 공급량으로 사용하고, 집행액이 전혀 없는
국가·분야만 약정액으로 대체한다.

```text
전체 공여국 포화도 =
  0.60 × 전체 공급량 경험백분위
  + 0.25 × 활동 공여국 수 경험백분위
  + 0.15 × 공여국 다양성

공여국 집중도 HHI = Σ(공여국별 공급비중²)
공여국 다양성 = 100 × (1 - HHI)
한국 점유율 = 100 × 한국 공급량 / 전체 공여국 공급량
```

공급량이 0이면 포화도와 다양성을 모두 0으로 둔다. 포화도가 높다는 것은
OECD 공공·ODA 공급과 참여 공여주체가 상대적으로 많다는 뜻이다. 민간기업
경쟁이나 사업 조달 경쟁률을 직접 측정하는 값은 아니다.

이제 `한국 공급 강도`와 `전체 공여국 포화도`를 분리할 수 있다.

- 한국 공급 강도 높음 + 전체 포화도 높음: 기존 협력은 강하지만 경쟁·중복 검토 필요
- 한국 공급 강도 높음 + 전체 포화도 낮음: 한국이 상대적으로 선도하는 분야
- 한국 점유율 낮음 + 전체 포화도 높음: 다수 공여국 시장에서 한국 비중이 작음
- 수요격차 높음 + 전체 포화도 낮음: 잠재적 미개척 후보

## 모델 3-2. 전체 공여국 공급 모멘텀

포화도는 최근 3년의 공급 규모를 보여주지만 증가·감소 방향은 말해주지 않는다.
2019~2024년 연도별 전체 공여국 공급량으로 별도 모멘텀 모델을 계산한다. 해당
국가·분야·연도에 양수 집행액이 있으면 이를 사용하고, 집행액 전체가 0인 경우에만
약정액을 사용한다.

극단적으로 큰 단일 사업의 영향을 줄이기 위해 `log(1 + 연간 공급량)`에
최소제곱 직선 기울기를 적합한다. 최근 변화는 마지막 2년 로그평균과 그 직전 2년
로그평균의 차이다.

```text
공급 모멘텀 =
  0.70 × 6개년 로그공급 기울기 경험백분위
  + 0.30 × 최근 2년 변화 경험백분위
```

모수적 직선만 믿지 않도록 Mann-Kendall 순위 추세의 τ와 tie 보정 p값, 연간
공급량 변동계수, 로그회귀 잔차 RMSE, 시작·종료연도 값이 모두 양수일 때의 CAGR도
함께 저장한다. τ가 0.6 이상이면 `sustained_growth`, -0.6 이하면
`sustained_decline`, 그 밖은 `mixed_or_flat`으로 표시한다.

모멘텀은 다른 국가·분야보다 최근 공급이 빠르게 늘었는지를 나타내는
`descriptive_only` 통계다. 수요가 증가했다거나 앞으로 예산이 늘어난다는 예측이
아니며, 연도 관측이 6개뿐이어서 p값의 검정력도 낮다. 후보 유형을 자동 변경하지
않고 사람이 포화도와 함께 읽도록 프로필에 별도 필드로 제공한다.

## 모델 4. 실행 준비도

최근 5년의 실제 수행 이력으로 사업을 실행할 기반이 있는지를 기술적으로
평가한다.

```text
실행준비도 =
  0.45 × 5년 사업 수 백분위
  + 0.30 × 수행기관 다양성 백분위
  + 0.25 × 사업 활동연도 수 백분위
```

이는 조달 준비, 현지 파트너 역량, 법적 실행 가능성을 직접 측정한 값이 아니다.
그런 세부 자료가 없는 상황에서 **과거 전달체계가 작동한 흔적**을 나타내는
기술통계다.

### 실행 가능성 게이트

실행 준비도 숫자에 서로 단위가 다른 위험요인을 임의로 가감하지 않는다. 준비도를
수치 기준축으로 유지하고, MOFA 여행경보·경제 프로필과 KOICA/MOFA 수집
커버리지를 별도의 실행 상태로 결합한다.

| 상태 | 규칙 |
|---|---|
| `screen_ready` | 경보 0~2, 필수 맥락 존재, 실행 준비도 50 이상 |
| `capacity_building_needed` | 필수 맥락은 있으나 실행 준비도 50 미만 |
| `manual_risk_review` | 여행경보 3단계 |
| `blocked_by_safety` | 여행경보 4단계 |
| `manual_economic_review` | 물가 10% 이상, 마이너스 성장 또는 실업률 10% 이상 |
| `insufficient_context` | 안전 또는 경제 프로필 등 필수 맥락 누락 |

여행경보 1~2단계는 일부 지역에만 적용될 수 있으므로 점수를 차감하지 않는다.
3단계는 자동 탈락이 아니라 수동 검토, 4단계만 자동 보류로 처리한다. 거시경제
기준 역시 실패확률 모형이 아니라 실사 대상을 찾는 규칙이다. 법률·조달·실명
상대기관 정보가 확보되기 전에는 이 결과를 최종 실행 가능 판정으로 사용하지 않는다.

## 모델 5. 정책 적합성

최근 3년 LOD·MOFA 근거 가운데 예산 승인·조달·이행약정(Tier A), MOU·타당성
조사·실무협의(Tier B)를 중심으로 계산한다.

```text
정책적합성 =
  0.60 × Tier A/B 가중 근거 강도
  + 0.20 × 출처 다양성
  + 0.20 × 참여기관 다양성
```

원천 `event_type`이 Tier A/B로 명시된 근거는 바로 사용할 수 있다. 일반
`press_mention` 문서에서는 시행약정·예산승인·조달·MOU·타당성조사·실무협의
등의 강한 문구를 찾되, 같은 문장 안에 대상 국가와 분야 표현이 함께 있을 때만
검토 후보를 만든다.

텍스트에서 추론한 후보는 `review_required`로 저장하며 자동 점수에서 제외한다.
서로 다른 두 검토자가 원문을 독립적으로 확인해 모두 승인한 경우에만
`human_approved`로 반영한다. 모두 거절하면 `human_rejected`, 의견이 다르면
`needs_adjudication`으로 분리한다. 검토자 쌍별 Cohen's kappa도 계산할 수 있다.
재분류를 실행해도 사람의 합의 결과는 보존된다.

자동 분류 대상이었던 461개 LOD/MOFA 일반 근거에서는 459개가 정책 실행 근거가
아니었고 2개가 검토 후보였다. 두 건 모두 2022년 문서이며 하나는 실제로
베트남이 아닌 한-싱가포르 문서가 베트남 레코드에 연결된 사례다. 이 두 건은
사람의 합의 전까지 계속 점수에서 제외된다.

별도로 외교부 원문의 국가·분야·사건유형을 확인해 작성한 공식 근거 파일에는
최근 문서 4개와 국가·분야 근거 8개가 있다. 이 파일은 엄격한 URL·날짜·분야
검사를 통과한 뒤 source-labelled Tier A/B로 적재된다. 2026년 기준 계산 결과는
다음과 같다. 점수가 낮아 보이는 주된 이유는 현재 출처 유형이 외교부 한 종류뿐이라
출처 다양성 항목이 제한되기 때문이다.

| 국가 | 분야 | 정책 적합성 | 승인 근거 |
|---|---|---:|---:|
| 인도네시아 | 보건 | 50.7 | 2 |
| 인도네시아 | 디지털 | 38.7 | 1 |
| 인도네시아 | 기후·환경 | 38.7 | 1 |
| 인도네시아 | 농업 | 34.7 | 1 |
| 인도네시아 | 직업훈련 | 34.7 | 1 |
| 베트남 | 디지털 | 38.7 | 1 |
| 몽골 | 기후·환경 | 30.7 | 1 |

표에 없는 국가·분야 조합은 0점으로 대체하지 않고 `insufficient_data`로 유지한다.

## 모델 6. 다중지표 미충족 수요

World Bank Indicators API는 인증키 없이 사용할 수 있다. 긴 다국가 JSON 요청은
502 오류가 반복돼, 공식 `downloadformat=csv` 방식으로 지표별 ZIP 파일을 한 번씩
받는다. 현재 9개 지표이므로 전체 비교군 수집도 API 요청 9회로 끝난다.

| 분야 | 공식 지표 | 수요 방향 |
|---|---|---|
| 교육 | `SE.SEC.ENRR` 중등교육 총취학률 | 낮을수록 수요가 큼 |
| 교육 | `SE.SEC.CMPT.LO.ZS` 전기중등 이수율 | 낮을수록 수요가 큼 |
| 교육 | `SE.PRM.CMPT.ZS` 초등 이수율 | 낮을수록 수요가 큼 |
| 디지털 | `IT.NET.USER.ZS` 인터넷 이용률 | 낮을수록 수요가 큼 |
| 디지털 | `IT.NET.BBND.P2` 고정 광대역 가입 | 낮을수록 수요가 큼 |
| 디지털 | `IT.CEL.SETS.P2` 이동통신 가입 | 낮을수록 수요가 큼 |
| 보건 | `SH_UHC_SCI` UHC 서비스 보장 | 낮을수록 수요가 큼 |
| 보건 | `SH.DYN.MORT` 5세 미만 사망률 | 높을수록 수요가 큼 |
| 보건 | `SH.STA.MMRT` 모성 사망비 | 높을수록 수요가 큼 |

각 국가의 최신 관측값은 스냅숏 연도 기준 7년 이내에서 선택한다. 지표 방향을
수요가 클수록 커지도록 맞춘 뒤, 동일 지표가 존재하는 OECD CRS 수원국 사이의
중간순위 경험백분위로 바꾼다.

```text
지표별 수요백분위 =
  100 × (더 작은 수요값의 수 + 0.5 × 같은 값의 수) / 비교국 수

분야별 수요점수 =
  관측 가능한 지표별 수요백분위의 가중평균
```

현재 가중치는 데이터 없이 중요도를 임의로 차등하지 않기 위해 모두 1이다. 분야당
3개 중 최소 2개 지표가 있어야 점수를 만들며, 그렇지 않으면 0점이 아니라
`insufficient_data`로 둔다. 관측연도 차이가 2년 이하면 최신성 1.0, 3~5년이면
0.7, 6~7년이면 0.4를 적용해 데이터 충족률에 반영한다. 점수 자체에는 최신성
가중치를 곱하지 않아 “오래된 국가의 수요가 낮다”는 잘못된 해석을 막는다.

지표 하나가 결론을 지배하는지 확인하기 위해 세 지표가 모두 있는 조합에는
leave-one-indicator-out 점수의 최솟값, 최댓값, 범위와 60점 임곗값 판정 안정성을
함께 저장한다.

이 값은 **개발 결과 격차를 찾기 위한 상대적 스크리닝 통계**다. 사업 예산 수요,
정부의 구매 의사, 한국과의 협력 의사 또는 인과효과를 직접 증명하지 않는다.
서로 상관된 지표와 국가별 보고시점 차이도 해석 시 고려해야 한다.

농업, 기후·환경, 직업훈련, 한국어·한국학, 문화·콘텐츠는 직접적이고 일관된
결과지표 계약이 아직 없으므로 점수를 만들지 않고 `insufficient_data`로 둔다.

## 후보 유형화

여섯 점수를 다시 임의의 종합점수로 합치지 않고 의사결정 규칙으로 분류한다.

- `priority_expansion`: 수요격차 60 이상, 연속성 60 이상,
  실행 상태 `screen_ready`, 실행 준비도 50 이상, 전체 포화도 70 미만
- `potential_whitespace`: 수요격차 60 이상, 전체 공여국 포화도 40 미만
- `competitive_market`: 수요격차 60 이상, 포화도 70 이상, 한국 점유율 10% 미만
- `continuation_candidate`: 연속성 60 이상이지만 우선확장 조건은 아님
- `monitor`: 다른 강한 규칙이 활성화되지 않음
- `needs_supply_data`: 전체 공여국 자료가 없음
- `needs_demand_data`: 분야별 수요지표가 없음

이 임곗값은 검증된 최적 경계가 아니라 명시적인 파일럿 운영 규칙이다. 실제
사업 선정 결과와 전문가 평가가 누적되면 순위학습 또는 비용민감 분류모형으로
교체할 수 있다.

실행 상태가 `manual_risk_review` 또는 `manual_economic_review`이면 후보 유형은
보존하되 결정 상태를 `review`로 내린다. `blocked_by_safety`면 `hold`로,
`insufficient_context`이면 자동 `screen`을 금지한다.

## 실행

전체 공여국 집계는 연도별 파일을 다시 실행해도 해당 연도를 교체하므로
중복되지 않는다.

```powershell
$env:PYTHONPATH = "src"
python scripts\import_all_donor_crs.py `
  "data\oecd\CRS 2019 data.zip" `
  "data\oecd\CRS 2020 data.zip" `
  "data\oecd\CRS 2021 data.zip" `
  "data\oecd\CRS 2022 data.zip" `
  "data\oecd\CRS 2023 data.zip" `
  "data\oecd\CRS 2024 data.zip" `
  --db data\statistical_signals_full.db
```

```powershell
$env:PYTHONPATH = "src"
python scripts\run_opportunity_models.py `
  --db data\statistical_signals_full.db `
  --fetch-world-bank `
  --world-bank-scope crs `
  --world-bank-transport bulk `
  --request-interval 1.5 `
  --output outputs\opportunity_models_full.json
```

API를 다시 호출하지 않고 DB에 저장된 지표만 재계산하려면
`--fetch-world-bank`를 뺀다.

```powershell
python scripts\run_opportunity_models.py `
  --db data\statistical_signals_full.db `
  --output outputs\opportunity_models_full.json
```

정책 근거 검토 후보를 확인한다.

```powershell
python scripts\review_policy_evidence.py `
  --db data\statistical_signals_full.db
```

검증된 공식 정책근거 파일을 적재하려면 다음 명령을 사용한다.

```powershell
python scripts\import_official_policy_evidence.py `
  --db data\statistical_signals_full.db
```

텍스트 추론 후보는 원문을 확인한 뒤 근거 ID를 승인하거나 거절한다. 승인·거절을
LLM에 위임해서는 안 되며 분석자가 원문 URL과 국가·분야 일치 여부를 확인해야
한다. 같은 후보를 두 명이 독립적으로 검토한다.

```powershell
python scripts\review_policy_evidence.py `
  --db data\statistical_signals_full.db `
  --reviewer analyst-a `
  --approve 123 `
  --include-decided

python scripts\review_policy_evidence.py `
  --db data\statistical_signals_full.db `
  --reviewer analyst-b `
  --approve 123 `
  --include-decided

python scripts\review_policy_evidence.py `
  --db data\statistical_signals_full.db `
  --reviewer analyst-a `
  --compare-reviewer analyst-b `
  --include-decided
```

두 검토자가 합의한 뒤 `run_opportunity_models.py`를 다시 실행하면 승인된 최근
3년 Tier A/B만 정책 적합성에 반영된다. 불일치 건은 별도 조정자가 원문을
확인하되 기존 두 라벨과 구분해 기록해야 한다.
