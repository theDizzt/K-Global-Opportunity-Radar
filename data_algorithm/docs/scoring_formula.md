# 점수 산식 문서

## 1. 정규화

모든 하위 지표는 0~100으로 변환한다. 예산·건수처럼 긴 꼬리를 가진 변수는 `log(1+x)` 후 고정 상한으로 나누며, 비율과 연속성은 선형 고정 상한을 사용한다. 3개 대상국만으로 백분위를 만들지 않아 대상국 추가 시 점수가 급변하는 문제를 줄였다.

주요 고정 상한은 최근예산 5천만, 활성사업 10건, 분야비중 60%, 외교신호 강도 4, 기관다양성 12개, 최근신호 10건, 학술기반 깊이 60이다. 상한을 넘는 값은 100점으로 절삭한다.

## 2. 분야 종합점수

`Opportunity = wD×Demand + wA×Alignment + wR×Readiness + wK×KoreaBase`

분야별 기본 가중치는 [sector_mapping.csv](country_mapping.csv)와 코드의 `taxonomy_v2.py`에 버전 관리한다. 사용자 가중치는 네 값이 모두 0 이상이고 합이 0보다 커야 하며, 입력 후 합이 1이 되도록 정규화한다.

제공 프리셋:

- 기업: 수요 35%, 정책 20%, 실행 35%, 한국기반 10%
- 공공기관: 수요 25%, 정책 35%, 실행 20%, 한국기반 20%
- 연구자: 수요 15%, 정책 20%, 실행 15%, 한국기반 50%

## 3. 추적성과 검증

- `score_snapshot`은 국가·분야·버전·기준일별 최종값을 저장한다.
- `score_component.detail_json`은 각 차원의 가중치와 하위 지표별 원시값·정규화값을 저장한다.
- `record_lineage`와 `evidence_document`를 통해 제공기관·수집일·자료기준일·원문 URL을 역추적한다.
- 각 분야 가중치를 ±20% 변경한 최저·최고값을 `sensitivity_low/high`로 저장한다.
- 같은 DB·기준일로 재계산한 SHA-256이 같아야 재현성 검증을 통과한다.

현재 KOICA API 장애로 사업 데이터가 0건이므로 검증 종합상태는 `REVIEW`다. API 재수집 성공 후 산출물을 다시 생성해야 최종 배포 판단을 할 수 있다.
